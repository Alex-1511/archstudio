# System Design
**Data model (implemented):** Project → Levels → Walls (thickness, height, material, openings, properties) / Rooms (boundary, target area). Stable ids on every element enable version diffing, BIM round-tripping and AI references.
**Persistence (implemented):** atomic write (temp + fsync + replace), `schema_version`, SHA-256 checksum (detects accidental corruption only: anyone editing the file can recompute it) and an optional HMAC-SHA256 signature that detects deliberate tampering for holders of no key. Cloud projects must also enforce integrity server-side. Next: autosave journal + crash recovery, Postgres for cloud projects, object storage for uploads/renders.
**Validation (implemented):** `Project.validate()` holds every invariant; it runs on creation, on import (`from_dict`, strict keys/types), after every history command, and before save. Numbers must be finite, real (no bool, no strings) and |x| ≤ 1e9 (finite alone still lets 1e308 overflow volumes to inf). Import additionally enforces a size cap and rejects `NaN`/`Infinity` JSON literals at parse time.
**History (implemented):** snapshot-based undo/redo that restores *in place* so object identity is stable (a graveyard revives removed objects on redo; it grows with edit history and will be bounded later), atomic apply with rollback, immutable named versions, id-level diff. Next: per-operation reversal and geometric (not just data) diff.
**Services (planned):** API gateway (auth, rate limit) · project service · AI service (agents, RAG) · geometry worker pool · render queue (GPU workers) · WebSocket hub. Jobs via Redis queue.
**Security (planned, Phase 1/9):** server-side API keys only; upload validation/size caps/sandboxed parsing; AI-generated scripts run only in a sandbox with explicit permission; per-project isolation; audit log.
**Schema migration rule:** any change to `Project.to_dict` bumps `SCHEMA` and ships a migration.
